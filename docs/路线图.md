# 路线图 · 从“能用”到“用得住”

> 当前版本 `0.5.1`。功能已经够跑完整闭环，接下来不是继续加功能，而是让它被用起来、用得久。

## 当前基线

- 面板：今天 / 书页 / 侧写 / 鲸汐 / 房间；
- 两个空间：书房记录，房间相处；
- 数据：Markdown + 独立 git，按天回退；
- 人设：v3，可开关；
- 记忆：房间目录 + 关键词搜索；
- 真实验证：2026-10-24 凌晨跑通过一次完整「晚安」。

**最大的现状不是缺功能，是还没形成使用习惯。**

## 五条优化原则

1. **先习惯，后功能**：一个每天用的 60 分流程，胜过一个月用一次的 90 分功能。
2. **文件优先**：日记、侧写、房间日志、心事都是 Markdown；索引和缓存随时可重建。
3. **约束下沉到工具**：不靠提示词“自觉”，能用工具挡住的就不写在规则里。
4. **小步、可回退**：每次改动一个提交；数据先快照，回退本身也 commit。
5. **人设靠使用迭代**：出戏的瞬间比设定集更有用。

## 五个方向

### 1. 用得住：把仪式变成习惯

**现状**：要自己想起来打开，容易断。

**下一步**
- 晚间提醒（默认 22:30）：“该去书房了”；
- 面板「今天」在未写时给一个轻提示，不弹窗、不红点；
- 断更不惩罚，给“补记昨天”入口；
- 周日一页周报：这周记住了什么、她自己的变化。

**验收**：连续 7 天自然使用，提醒最多响一次。

### 2. 记得住：侧写与记忆

**现状**：目录 + 关键词够用；侧写只能整篇重写；心事只读。

**下一步**
- 侧写结构化追加：`section + entries + evidence`，避免整篇覆盖；
- 心事写入工具 + 面板编辑；
- 房间日志可标 `pinned`（常提的事、重要的日子）；
- 记忆目录分三栏：最近 / 常提 / 重要；
- 向量检索只在“关键词搜不到”变成常态时再加，接口先留好。

**验收**：问“上次说的那件事”十秒内能找到；侧写只增不丢。

### 3. 两个空间：房间体验

**现状**：房间列表、新房间、上下文提示都有；皮肤未做，手动改名没有。

**下一步**
- 房间手动改名、归档；
- 房间开场白/状态（“她在擦杯子”“她在窗边”）；
- 房间皮肤：先 CSS，稳不住再接管视图；
- 房间内一键“换一间”；
- 新房间带 carry card：最近房间日志 + 侧写摘要，避免失忆。

**验收**：换房间不失忆；进房间像进房间，不像进设置页。

### 4. 不会丢：备份与信任

**现状**：本地 git + 导出；没有远程备份。

**下一步**
- 面板里一键 push 到私有仓库；
- 显示上次备份时间、失败原因；
- 导入/恢复向导（换手机 10 分钟能恢复）；
- 隐私检查：private 不进侧写、不进导出。

**验收**：做一次恢复演练；误删能回退。

### 5. 能长大：工程与发布

**现状**：15 个测试；未发 GitHub Release；i18n 只做了一半。

**下一步**
- GitHub Release + 截图 + 安装说明；
- i18n：日历、工具描述、面板文案；
- 长历史性能：书页虚拟列表、搜索索引；
- 安全：房间/日记硬隔离、接口限流；
- 1.0 冻结工具 schema。

**验收**：别人按 README 能装上；升级不破坏数据。

## 现在不建议做

| 想法 | 为什么先不做 |
| --- | --- |
| 向量记忆 | 目录 + 关键词够用；等搜不到成为常态 |
| 面板内聊天前端 | 先做房间皮肤；聊天前端是 1–2 周的维护 |
| Agent Teams 做房间 | 多 session 已经够；teams 是并行干活，不是聊天 |
| 自动抽取记忆 | 对日记太黑箱；宁可她自己翻 |

## 里程碑

| 版本 | 主题 | 核心 |
| --- | --- | --- |
| 0.6 | 习惯 | 晚间提醒、补记、周报 |

| 0.8 | 房间 | 改名/归档、皮肤、carry card |

## 三个月目标

- 连续 30 天有记录（允许补记）；
- 3 个房间、20 条房间日志，能搜到、能接上；
- 侧写 30 条以上，旧条目一条不丢；
- 做一次完整恢复演练；
- 人设“出戏”的瞬间明显变少。

数字不是 KPI；它们只用来判断“这套东西是不是真的在生活里站住了”。
