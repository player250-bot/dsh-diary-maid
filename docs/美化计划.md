# 美化与聊天计划

> 记录"打开房间后换皮肤 / 多房间对话 / 面板内聊天"三条路线的可行性、成本与顺序。
> 原则：**美化最后做；主体功能先跑通；日记文件始终是唯一数据源。**

---

## 1. 先回答三个"能不能"

### 1.1 打开之后切换对话区皮肤

能，两种做法：

| 做法 | 怎么实现 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **注入样式** | 进入房间时给页面打标记，注入只在房间模式生效的 CSS | 快（1–2 天）；不动渲染逻辑 | 依赖 DSH 现有类名，升级可能失效 |
| **接管渲染** | 注册 `conversation.view`，自己画消息/思考/工具卡片 | 稳；可完全自定义 | 要重画聊天 UI（3–5 天） |
| **fork 会话 UI** | 像 `dsh-chat-focus` 一样整包替换 `dsh-client-ui-conversation` | 自由度最高 | 上游一改就要跟，长期维护 |

"只有打开之后才包裹"没问题：进入房间打标记、退出移除。难点不在开关，在"包裹到什么程度"。

### 1.2 不同按钮进入不同对话

能，而且这是 DSH 原生能力。每个"房间"就是一个独立 **session**：

- 新建：`startSession`；
- 切换：`openSession(id)`；
- 映射：`房间名 → sessionId` 存进 `.diary/rooms.json`，下次点同一个房间回到原对话。

所有 session 共享同一个日记本目录；**session 只是上下文容器，日记内容仍然只在 vault 的 Markdown 文件里**。

不同房间想要不同人设：给新 session 选不同的 agent preset（这一步要额外做，v0.5 之后）。

### 1.3 前端输入 → 后台路由到不同对话 → 思考/结果回传

能，这就是做一个"聊天前端"。DSH 自己就是这么实现的。

需要接的东西：

- 发送 prompt、订阅流式输出；
- 思考块（reasoning）折叠展示；
- 工具调用卡片、审批（approve/deny）；
- 中断、错误重试、附件、上下文压缩。

| 版本 | 内容 | 成本 |
| --- | --- | --- |
| demo | 纯文本 + 流式 + 一个房间 | 2–3 天 |
| 可用 | 多房间、思考块、工具卡片、审批 | 1–2 周 |
| 稳定 | 断线重连、附件、长对话、升级跟进 | 持续 |

## 2. Agent Teams 适不适合

**不适合做房间/聊天后端。**

Agent Teams 是"并行干活"的机制：一个 Lead 带几个 teammate，各自独立上下文，互相发消息、派任务。

放到这里的问题：

1. 每个 teammate 是一整个 agent，启动和切换都重；
2. 前台还得写一套订阅/渲染，等于 1.3 的工作量；
3. **多个 agent 同时写同一份日记文件会打架**——git 只能事后回退，不能自动合并。

正解是"多 session + 不同 preset"，不是 teams。

Teams 可以做**后台**：让一个 teammate 翻旧日记、整理侧写、查资料，主 agent 继续聊。这个有价值，但不该放到前台。

## 3. 推荐顺序

### 第 ① 步：多会话房间（2–3 天，低风险）

- 房间列表（面板里的「房间」tab）；
- 点哪个进哪个 session；没有就新建；
- `rooms.json` 记住映射；
- 日记文件、git、工具全部不变。

**验收**：点「书房」和「海边」进去是两段不同的对话，但写的是同一本日记。

### 第 ② 步：房间皮肤（3–5 天，中风险）

- 进入房间时换背景、气泡、输入框提示；
- 先做 CSS 注入版；
- 不够再注册 `conversation.view` 自己渲染。

**验收**：进房间像进了房间，退出恢复原样；不影响正常对话。

### 第 ③ 步：面板内聊天（1–2 周，高风险）

- 面板里渲染消息流 + 输入框；
- 后台路由到不同 session；
- 思考块、工具卡片、审批逐步补齐。

**验收**：不离开面板就能聊完一轮访谈，并落进访谈日志。

只有确实想"不离开面板"才做这一步；否则 DSH 原生聊天已经够好。

## 4. 成本与风险

| 阶段 | 成本 | 风险 | 维护 |
| --- | --- | --- | --- |
| 多会话房间 | 2–3 天 | 低 | 低 |
| 房间皮肤（CSS） | 1–2 天 | 中（类名变化） | 低 |
| 房间皮肤（view） | 3–5 天 | 中 | 中 |
| 面板内聊天 | 1–2 周 | 高 | 高 |

## 5. 参考项目

- [dsh-chat-focus](https://github.com/supergameboy/dsh-chat-focus)：fork 会话 UI，气泡、折叠运行时活动、深度自定义——最接近"包裹"的完整做法。
- [dsh-customizable-theme](https://github.com/km5473/dsh-customizable-theme)：背景、主题色、表情包、文案，纯皮肤路线。
- [OrinVoss/dsh-plugins](https://github.com/OrinVoss/dsh-plugins)：社区插件集，含多套皮肤、桌宠、长期记忆。
- [SillyTavern](https://github.com/SillyTavern/SillyTavern)：完整的角色聊天前端——"脱离 DSH"的终点形态，也是成本参照。

## 6. 待定

1. 房间是"同一人设的多个话题"，还是"多个角色"？后者需要 preset。
2. 皮肤走 CSS 注入还是 view？先做 CSS，看效果再决定。
3. 面板内聊天要不要支持工具审批？不支持就只能做纯聊天，日记仍回主对话写。
