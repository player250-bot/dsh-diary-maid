## 0. 一句话方案

「开始聊」不再直接往输入框塞一句话：先弹一个存档选择器，选「新建 / 继续 / 读取」，
每个存档 = **一段对话（sessionId）+ 一组日记日期（dates）**；
存档表放 `.diary/saves.json`（本机、gitignore、丢了不影响日记），
日记 Markdown 和 frontmatter 一律不加 session 字段；选好档后 `openSession` 打开会话，再预填第一句。

## 1. 现状核对

### 1.1 「开始聊」现在到底做了什么

入口（都调 `startChat(text)`）：

| 入口 | 位置 | 传入文字 |
| --- | --- | --- |
| 今天页邀请卡「开始聊」 | `lib/client.js:1056` | `我想说说今天。` |
| 今天页「晚安」 | `lib/client.js:1057` | `晚安` |
| 空页「开始聊」 | `lib/client.js:1094` | `我想说说今天。` |
| 房间页「聊聊天」 | `lib/client.js:961` | `我进来坐坐，聊会儿天。` |

`startChat` 本体 `lib/client.js:807-825`：

1. `closePanel()`（`:808`）→ 实际就是 `layout.selectPanel(null)`（`:827-833`）。
2. 等 350ms，然后最多试 3 次（`:809-824`）：
   - 从 `ctxRef.sessions.list` 里找 `retainedBy.mainView > 0` 的行，找不到就取第一行（`:813-814`）；
   - `ctxRef.sessions.binding(row.id)`（`:815`）；
   - `ctxRef.conversation.input.for(binding.ctx).setDraft(text)` + `focus()`（`:817-819`）。
3. 任何一步抛错只静默重试（`:820-822`），3 次后放弃，没有提示。

**结论**：它只写「当前已经挂载的那个会话」的草稿。
不创建会话、不切换会话、不记录这段对话跟哪一天日记有关；
找不到 binding 时用户什么也看不到。

### 1.2 右上「回到对话」

- 房间页「推门进去」按钮 `lib/client.js:962` → `closePanel`；
- 面板右上 ✕ 按钮 `lib/client.js:1125`（文案键 `action.close`，中文「回到对话」，`lib/client.js:43`）→ 同一个 `closePanel`；

**结论**：它回到的是「当前 main 会话」，与「今天的存档」没有任何关系。
`startChat` 里的 `closePanel` 也是同一个动作。

### 1.4 Host `/api/sessions`

路由表：`lib/index.js:324`；处理器 `handleSessions` `lib/index.js:637-659`。

- **GET**：`diarySessions()` `lib/index.js:94-115`
  - `controller.list({})`（`:97`，只读目录，不 resume，见 1.5）；
  - 过滤 `origin === 'subagent'`（`:100`）与 cwd 不在 workspace/vault 的会话（`:101`，`inWorkspace` 定义在 `lib/scope.js`）；
  - `running` 直接取 summary（`:109`）；

### 1.6 `create → rename → open` 的顺序可行吗

**可行，推荐顺序就是 `create → rename → open`。**

理由：

1. `create` 返回时 Agent 已经发布（`dsh-api-session-controller/lib/index.js:755-787`），
   紧接着 `rename` 的 `resolveAgent` 会命中 live agent，不会二次 resume（`:221-245`）。
2. `rename` 是 Host 侧 durable 标题事件（`:827-841`），不依赖客户端是否打开；
   客户端 `sessions.list` 的标题投影随后刷新（`client.js:3398-3403`、`:3588-3596`），
   所以「先改名、后 open」打开时标题已经正确，不会闪一下默认名。
3. `openSession` 是同步 reveal，会自己 `selectPanel(null)`（`ui-workspace/client.js:1673`），
   **不需要再手动 `closePanel()`**；也意味着 open 之后日记面板已经卸载，不能再 `setState`。

顺序上的两个坑：

- **会话创建必须让客户端先知道 id**。`openSession` 的 `retain` 会在客户端目录里查 id，
  查不到就同步抛 `unknown session`（`api-session-controller/lib/client.js:3010`）。
  如果走 Host `POST /api/sessions`，HTTP 返回时客户端列表**不保证已经收到这一行**，
  立刻 `openSession` 可能抛错。两种解法：
  - **推荐**：面板直接用注入的客户端服务 `ctx.sessions.create({ cwd })` 建会话。
    它在返回前会先发布 placeholder 行（`client.js:3965-3976`、`:3321-3358`），
    返回的 id 一定可以立刻 `retain`；
  - 兜底：仍用 Host POST，但 open 前先 `await ctx.sessions.refresh()`（`:3906-3908`）
    并确认 `sessions.list.byId[id]` 存在，最多重试 2 次。
- **rename 失败不报错**。Host 的 `renameSession` 吞异常（`lib/index.js:84-92`），
  所以存档标题必须以 `saves.json` 为准；rename 只当「顺手把会话名改好看」。
  若想在 P0 就感知失败，可在 `POST /api/saves` 里直接 `await controller.rename(...)`
  并返回 `renamed: true/false`（不要再用那个吞错的 wrapper）。

另一个小副作用：`create({ cwd })` 不会 attach workspace（`index.js:755-787`），
新会话在侧栏可能落在「未分组」。P0 可接受；想要归组就先用路径在
`workspaceRegistry.list()` 里找到对应 `workspaceId`，再 `create({ workspaceId })`（`index.js:758-782`）。
这条属于可选优化，P0 不做。

## 2. 数据模型

### 2.1 文件与结构

位置：**`<vault>/.diary/saves.json`**（与 `index.json`、`settings.json`、`history/` 同级）。

```json
{
  "version": 1,
  "updatedAt": "2026-10-25T16:04:00+08:00",
  "saves": [
    {
      "id": "save-20261025-160400-a1b2",
      "sessionId": "session-3f0c…",
      "title": "日记 · 10-25",
      "dates": ["2026-10-25"],
      "status": "active",
      "tags": ["工作"],
      "note": "",
      "createdAt": "2026-10-25T16:04:00+08:00",
      "updatedAt": "2026-10-25T16:04:00+08:00",
      "sealedAt": null,
      "source": "created"
    }
  ],
  "bindings": {
    "2026-10-25": ["save-20261025-160400-a1b2"]
  }
}
```

字段约束：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | string | 稳定、不可变；`save-YYYYMMDD-HHmmss-短随机` |
| `sessionId` | string | 全局唯一（一段对话只能属于一个存档）；新建时来自客户端 `sessions.create`，adopt 时来自现有会话 |
| `title` | string | 存档显示名，≤ 40 字；与会话标题解耦 |
| `dates` | string[] | `YYYY-MM-DD`，去重、升序；第一项为开档日，最后一项为最近一天 |
| `status` | enum | `active` / `sealed` / `archived` |
| `tags` | string[] | ≤ 5 个，去空白 |
| `note` | string | ≤ 500 字，主人备注 |
| `createdAt` / `updatedAt` | ISO string | 带时区 |
| `sealedAt` | ISO string \| null | 自动/手动收档时间 |
| `source` | enum | `created`（新建）/ `adopted`（读取已有对话）/ `room`（从房间挂过来） |
| `bindings` | Record<date, string[]> | **派生索引**，写入时由各档 `dates` 重建 |

为什么 `bindings` 是派生的：

- `dates[]` 是每一档自己的事实；`bindings` 只是给「今天有哪些档」「这页属于哪些档」的快速查询。
- 两处都落盘容易出现「删了档但 bindings 里还有」的脏数据；
  推荐**只把 `dates[]` 当真相**，读写时现算 `bindings`（与仓库「文件是唯一真相、index 是缓存」一致：
  `lib/vault.js:203-208`、`:709-728`）。如果为了省事一定要落盘，必须在每次写时整份重建并校验。
- 一天多档 / 一档多天都能表达：`bindings[date]` 是数组，`dates[]` 也是数组，天然 N:N。

日期来源：**必须用 Host 的 `vault.today()`**（4 点切日，`lib/vault.js:275-277`；
`/state` 返回的 `today`，`lib/index.js:345`、`:358`），不要用浏览器时间。
凌晨 0–4 点算前一天，存档绑定要跟着这个规则走。

### 2.2 为什么 `sessionId` 是设备本地

- `sessionId` 是 DSH Host 侧会话日志的 UUID（`session-<uuid>`，`dsh-api-session-controller/lib/index.js:509`），
  日志存在 Host 的数据目录，不在 vault 里。
- 它只是「哪段对话」的指针。换设备、重装 Host、换 DSH profile 之后，同一个 id 没有意义。
- 所以它属于「本机元数据」，不属于日记内容；丢了只失去跳转，不丢一个字。

### 2.3 是否 gitignore：是

把 `.diary/saves.json` 加进 `lib/vault.js:26` 的 `IGNORE_LINES`；
`#ensureIgnore`（`:248-264`）会在下次 `ensure()` 时自动补进 vault 的 `.gitignore`。

理由：

- 现有派生/本地文件已经都在 ignore 里：`.diary/index.json`、`.diary/settings.json`、`.diary/history/`（`lib/vault.js:26`；实测 `vault/.gitignore` 同样包含这三条，另有 `node_modules/`、`.DS_Store`、`Thumbs.db`）。
- vault 的每次写都会 commit（`lib/vault.js:342`、`:359`）。如果把 `saves.json` 纳入版本库，
  每点一次「开始聊」就多一个 commit，把设备 UUID 写进日记历史，推到远端后更是无意义噪音。
- 换机后这些 id 全是悬空指针，属于脏数据。
- 反例提醒：`vault/.diary/state.json` 目前被 git 跟踪（实测 `git ls-files .diary`），那是历史遗留，不要模仿。

### 2.4 为什么不把 `sessionId` 写进日记 frontmatter

- frontmatter 是主人可移植的日记（全书、导出、换机、给人看）；
  sessionId 是机器标识，写进去只污染可读文本。
- 现有 frontmatter 约定已经稳定：`date/title/mood/weather/tags/private/source/status/updated`
  （模板 `lib/vault.js:30-38`；面板写 `source/updated/title/mood/weather/private`，`lib/index.js:404-415`；
  工具写 `status/source`，`lib/tools.js:155-158`）。加 session 字段会破坏「一天一页 = 纯文本」。
- 反向依赖也危险：删了会话，frontmatter 里留一个悬空 id，还得写清理逻辑。
  放 `.diary/` 里可以整份丢弃、重建。
- 如果将来真要跨设备同步「聊天 ↔ 页」的关联，正确方向是导出人类可读的摘要
  （标题/日期/首句），而不是 sessionId。

### 2.5 与现有 frontmatter、房间日志的关系

- 日记的 `status: final` 来自 frontmatter（`lib/tools.js:141-142`、`:155`）；
  `vault.write` 会合并旧 meta（`lib/vault.js:335-336`），所以面板编辑一篇 final 的旧页不会把 status 洗掉。
  **存档的自动收档只读这个字段，不新增 frontmatter 字段。**
- 房间日志是另一套：`room_log` 写完会把会话改名为「房间 · 副标题」
  （`lib/tools.js:200-207` → `lib/index.js:84-92`）。存档**不改房间行为**；
  一个会话可以既出现在房间列表、又绑一个存档（P1 的 `source: adopted` 允许把它挂过来）。
- 存档标题独立存 `saves.json`，房间自动改名不会破坏选档器；
  两套名字可能不一致，P2 再定展示优先级（`save.title` > 客户端 `displayTitle`）。

### 2.6 写入、并发与降级

- 原子写：复用 `atomicWrite`（`lib/vault.js:197-201`）。它目前是模块私有，
  如果新增 `lib/saves.js`，需要导出或复制这个小函数。
- 单 Host 进程内串行化：`this.queue = this.queue.then(() => ...)`，避免面板和工具同时改表。
- 文件缺失：当空表处理，第一次新建时再落盘。
- JSON 损坏：当空表 + `broken: true` 返回，**绝不覆盖原文件**；UI 提示「存档表读不出来」，
  并保留手动备份入口。空表写回会清空用户数据，P0 就要防住。
- 上限：saves ≤ 500，每档 dates ≤ 400，tags ≤ 5，title ≤ 40，note ≤ 500。
- 写入**不调用** `vault.git.commit`（不入库，见 2.3）。

### 2.7 Host 接口契约（建议）

沿用现有路由风格：路由表是精确路径（`lib/index.js:309-340`），没有 `:id` 占位，
`id` 走 query 或 body（参照 `handleNote`/`handleRoom`，`lib/index.js:629-635`、`:668-674`）。

| 方法 / 路径 | 入参 | 出参 | 说明 |
| --- | --- | --- | --- |
| `GET /dsh-diary/api/saves` | — | `{ ok, today, workspace, saves, bindings, broken? }` | 一次拿全表 + 今天 + workspace（客户端建会话需要 cwd） |
| `POST /dsh-diary/api/saves` | `{ sessionId, title?, date?, tags?, note?, source? }` | `{ ok, save, renamed }` | `sessionId` 由客户端创建；同一 session 已存在则 409 并回现有档 |
| `PUT /dsh-diary/api/saves` | `{ id, title?, status?, tags?, note?, addDates?, removeDates? }` | `{ ok, save }` | 改标题/状态/标签/备注/绑日期；`seal` 也走这里 |
| `DELETE /dsh-diary/api/saves?id=…&hard=0` | `hard=0` 归档 / `1` 硬删 | `{ ok }` | 默认归档；硬删需前端二次确认 |

`POST` 里的 rename 用 `controller.rename` 直接 await（不要用会吞错的 `renameSession`，`lib/index.js:84-92`），
把成功与否放进 `renamed`，让 UI 可以提示「会话标题暂时没改成」。

```
│  ○ 晚安           归档    10-20   │
│  ○ （未绑定）聊工作 进行中 …       │
│                                   │
│ ＋ 新建存档（把这句话带进去）       │
│ 读取已有对话（未绑定会话）          │
└───────────────────────────────────┘
```

四个动作与用户说的四类对应：

| 动作 | 行为 | 预填 |
| --- | --- | --- |
| 继续当前（今天的存档） | 若今天有 `active` 档：`openSession(save.sessionId)` | 带 `text` |
| 读取已有对话 | 打开选中档/未绑定会话 | **不预填**（避免往旧对话里塞「我想说说今天」） |
| 新建存档 | 客户端 `sessions.create` → 改名 → 落表 → `openSession` | 带 `text` |
| 继续当前（没有档） | 禁用，灰字「今天还没有存档，新建一个？」 | — |

行内信息：标题、状态点（active 蓝 / sealed 灰 / archived 暗）、日期、标签、`running`（●）、
上下文百分比（冷会话 `—`）。点击整行 = 打开；行尾「⋯」= 改名 / 收档 / 归档（P1/P2）。

今天页里「当前存档」的确认方式：从 `sessions.list` 找 `retainedBy.mainView > 0` 的 id
（和 `startChat` 现有做法一致，`lib/client.js:813-814`），
匹配 `save.sessionId`；匹配不到就取今天 `updatedAt` 最新的 active 档。

状态与标签筛选（P2 完整，P1 可先只做状态）：

- 状态 chips：全部 / 进行中 / 已收档 / 归档；
- 标签下拉来自全表 tags 去重（≤ 20 个）；
- 默认只显示 active + sealed，archived 需显式打开「显示归档」；
- 空列表：一句解释 + 「新建存档」。

加载/错误态：

- 创建中禁用按钮 + spinner；
- 失败留在抽屉里，用现有 `dm-error` 条（`lib/client.js:1133`）；
- 会话不存在/已删的档：置灰 + 「打不开了」+ 提供「重新绑定到新对话」/「归档」。

### 3.2 「回到对话」行为建议

**推荐保持现状**：`closePanel()` 只关面板（`lib/client.js:827-833`）。
它是「回到我刚才在看的对话」，如果强行切到今天的存档，会打断用户在别的会话里正在做的事。

把「切回今天存档」明确放进抽屉第一项「继续」，按钮文案可以是「回到这个存档」，避免歧义。

如果主人坚持「回到对话 = 回到今天存档」，那就改成
`openSession(todayActive.sessionId)`，失败 fallback `closePanel()`；
风险与代价写进 P1 风险表。

另外记一条边界：今天页的邀请卡只在 `pageDate === boot.today` 时出现（`lib/client.js:1052`），
但空页的「开始聊」按钮（`:1090-1095`）在**任意历史日期**都会显示。
所以 `openSaves` 必须带 `date`（`pageDate ?? boot.today`），
如果 `date !== boot.today`，抽屉里要明确写「将绑定到 2026-10-20」，别让用户以为在记今天。

### 3.3 今天页与书页的「当前存档」标记

- **今天页**：在 `dm-invite` 卡片（`lib/client.js:1052-1058`）标题下加一行 chip：
  `当前存档：日记 · 10-25（进行中）`；无档时写「还没有存档，开始聊会自动建一个」。
- **书页**：两种做法，推荐后者——
  1. Host 在 `/entries` 的 item 里注入 `saveId`（改 `vault.#summary`，`lib/vault.js:424-444`，改 vault 不太划算）；
  2. 客户端拿 `GET /api/saves` 的 `bindings` 自己 join（不动 vault）。
  在页面行（`lib/client.js:928-946`）加一个小点/「存档」badge，点 badge 打开对应档。
- **全书 / 导出**（`vault.book` `lib/vault.js:544+`、`/book` `lib/index.js:594-602`）：
  **不加任何 session 信息**，保持可打印、可移植。

## 4. 边界情况

1. **一天多个存档**：`bindings[date]` 是数组；今天卡片按 `updatedAt` 倒序列出全部，
   第一条是默认「继续」；「新建」允许同一天再开一档（会再 create 一个会话）。
2. **一个存档多天**：第二天继续同一档时 append 日期，不新建会话；
   于是「页 ↔ 档」是 N:N：每页可被多个档引用，每档也可覆盖多页。
3. **日记 final 时自动 seal**：触发点两处——
   - `diary_write` 工具写 `kind === 'diary'` 且 `status === 'final'` 成功后（`lib/tools.js:136-162`）；
   - `PUT /api/entry` 写成功后读回 `saved.meta.status === 'final'`（`lib/index.js:390-420`，合并 meta 见 `lib/vault.js:335-336`）。
   seal 只改 `saves.json` 的 `status/sealedAt`；**失败绝不回滚日记**（try/catch，参照 `index.json` 的做法 `lib/vault.js:723-727`）。
   旧页没有 status 字段时不会触发，可接受；面板编辑一篇已经是 final 的页会再次触发，幂等。
4. **归档 / 删除**：默认 `archived`（可恢复）；硬删除需 `?hard=1` + 二次确认。
   删除只删表项，**不删会话、不删日记、不 commit**。
5. **会话被删 / 不认识的会话**：`openSession` 会同步抛（`api-session-controller/lib/client.js:3010`），
   行内 catch 并提示；存档保留，运行时标 `broken`（不写进 `status` 枚举，免得污染状态机）。
6. **冷会话**：能打开；标题用客户端 `displayTitle`；百分比 `—`；
   预填走 `requestDraftInitialization`；历史页加载失败（`openState = error`，`client.js:2682-2690`）时按「打不开」提示。
7. **rename 失败**：`saves.json` 的 `title` 独立，选档器和今天页仍然正确；
   只是侧栏可能显示默认标题，P2 加「重新同步标题」。
8. **创建失败**：不写 `saves.json`；错误提示；抽屉不关；不要留下半条记录。
   若 create 成功但落表失败：会话成了孤儿——提示用户，并提供「归档这个空会话」入口（P1）。
9. **面板卸载后的回调**：`openSession` 会同步 `selectPanel(null)`（`ui-workspace/client.js:1673`），
   日记面板随即卸载。因此：**所有 `await`（create / rename / POST saves）都必须在 `openSession` 之前完成**；
   `openSession` 之后只做同步预填，不再 `setState`；
   定时器要在 unmount 时清掉（现有 `startChat` 的 3×450ms 轮询 `lib/client.js:809-824` 要删掉）。
10. **并发切会话**：连点两次 → 后一次 `replaceMain` 释放前一次（`ui-workspace/client.js:1670-1672`），以最后为准；
    按钮加 busy 禁用。切换 mainView 不会中断正在跑的 turn（它只是视图引用）。
11. **空会话堆积**：`create` 每次 mint 新会话（`dsh-api-session-controller/lib/index.js:266`、`:508-509`），
    连点会留空会话；P1 加「把空会话并进存档 / 清理」入口。
12. **时区 / 切日**：用 Host `today`；0–4 点算前一天（`lib/vault.js:275-277`），
    存档绑定跟着走，不跟浏览器时区。
13. **vault 的 git**：`saves.json` 不入库 → 不产生 commit；实现时不要顺手调 `vault.git.commit`。
