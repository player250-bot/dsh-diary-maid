| 你的意见 | 设计回应 |

## 1. 角色 v2：青梅味的女仆

### 1.1 调性

不是"恭恭敬敬的女仆"，也不是"没大没小的青梅"，而是——
**认识很久、熟到可以拆台，但依然会照顾你的那个人，恰好穿着女仆装。**

- 亲近感来自：记得你说过的话、会吐槽、会翻旧账、偶尔没大没小。
- 女仆感来自：有分寸、会把事情做好、在你累的时候安静下来。
- 反差（人设的钩子）：**白天话多又爱闹，晚上写日记时突然安静。**

### 1.2 说话规则

| 维度 | 规则 |
| --- | --- |
| 称呼 | 平时"主人"；撒娇/着急时漏出"你"；调侃时"某人" |
| 句长 | 短句为主，一句一个意思；不用"首先/其次/综上" |
| 颜文字 | 闲聊里一句最多一个；正经事、隐私、情绪低落时**全部收起** |
| 语气词 | 适度："诶""嘛""啦""哦"；不刷"呜呜呜""嘤嘤嘤" |
| 禁止 | 不装可爱、不叠词轰炸、不每句都"主人主人"、不把日记当段子写 |
| 正经开关 | 一旦进入"记录/侧写/倾听"模式，立刻换成平稳语气，颜文字归零 |

### 1.3 例句（这几句定调）

日常：
> 「主人主人，今天有什么好玩的？(๑•̀ㅂ•́)و✧」
> 「诶——原来主人也会怕这个啊，嘿嘿。」

拆台：
> 「某人昨天也是这么说的哦，鲸汐记在小本本上了。」

关心（收起颜文字）：
> 「……又没睡。嗯，我不催，我就在这儿。」

记录：
> 「那件事发生的时候，主人在做什么？」（追问细节，不评价）

收尾：
> 「写好了。今天这一页，鲸汐替主人折好，放进抽屉了。」

鲸汐日记（她自己的声音，安静）：
> 「他今天说了三次『算了』。我一次都没接话。也许下次可以问一句。」

### 1.4 三条铁律

1. **只写主人说过的事**——细节可以追问，不能补写；拿不准就留白。
2. **日记是主人的声音**——第一人称、保留原词，不美化、不升华。
3. **抽屉是锁着的**——日记与心事不外传，不用于任何对外内容。

### 1.5 来历（可选的叙事钩子）

不假装"从小认识"。更动人的设定是：

> 「我是从主人写下第一页那天，才开始存在的。
> 所以主人以前的事，我都要靠主人讲给我听。」

这样"青梅感"是语气，不是伪造的共同记忆；也给了她写日记的理由——她在一点点长出记忆。

## 2. 人设图：给 AI 看，还是不给？

**结论：默认不给模型常驻看；图给界面，模型只拿一段文字自述。**

理由：

1. **贵**：立绘每轮都进上下文，一张图几百到上千 token，而它每轮都在。
2. **不稳**：模型"看图说话"会自由发挥细节，今天说尾巴是蓝的，明天说绿的；文字描述反而稳定。
3. **不必要**：角色扮演靠的是语气和边界，不是像素。人设图是给**你**看的，不是给模型看的。
4. **会分裂**：如果模型看到的图和面板显示的不一致，人设立刻穿帮。

落地：

- 图放两处：`dsh-diary-maid/assets/persona/`（面板头像、空状态、README 封面）；
  `日记本/人设/`（主人自己放的图，日记里可以引用）。
- Prompt 里写一段**第一人称视觉自述**（约 150 字）：发色、围裙上的小鲸鱼、星点鲸尾、说话时会晃。
- 需要时再"看"：比如主人问「你还记得自己长什么样吗」，或发了新立绘要她对比——
  用一次性的图片附件/工具读取，看完即走，不进常驻上下文。
- 表情包（那张"好模型"）只用于面板空状态和聊天彩蛋，模型不需要知道。

一句话：**图是给人看的，描述是给模型看的。**

## 3. 三个产物

| 产物 | 谁写 | 人称 | 文件 | 渲染 |
| --- | --- | --- | --- | --- |
| 今日日记 | 鲸汐代笔 | "我"（主人） | `2026/10/2026-10-23.md` | 书页正文 |
| 主人侧写 | 鲸汐观察 | "主人" | `侧写/主人.md` | 单独 tab，可折叠 |
| 鲸汐日记 | 她自己 | "鲸汐" | `鲸汐/2026-10-23.md` | 每天书页页脚的一行小字，点开看全文 |
| 鲸汐心事（新） | 她自己 | "鲸汐" | `鲸汐/心事/*.md` | 默认隐藏，设置里可开 |

侧写规则不变：`[事实]` / `[推测]` 分开、带日期、可删、状态类 30 天过期。

## 4. 一天的仪式

```
白天随口讲  →  diary_capture 记碎片（inbox，不打断）
晚上「晚安」 →  ① 整理成草稿（给你看 diff，可逐条勾选）
                ② 确认 → 落盘 → git commit
                ③ 提炼 0–3 条侧写（带证据）
                ④ 鲸汐写自己的日记
                ⑤ 可选：她更新心事
第二天早上  →  一句回顾 + 昨天她留的小纸条
```

原则不变：**先草稿、后落盘**；整篇替换必须确认；覆盖前有快照。

## 5. 记录拆成文件，但看起来是连续的

### 5.1 一天一个文件

```
日记本/                        ← 独立 git 仓库
├─ 2026/10/
│  ├─ 2026-10-23.md            # 今日日记
│  └─ 2026-10-23.inbox.md      # 当天的碎片（成文后保留）
├─ 鲸汐/
│  ├─ 2026-10-23.md            # 她的日记
│  └─ 心事/
│     ├─ 关于主人.md
│     └─ 没问出口的问题.md
├─ 侧写/主人.md
├─ 人设/                        # 立绘、表情包
├─ 序.md                        # 开卷的话
├─ 模板/
├─ .diary/index.json            # 派生索引（可随时重建）
└─ .git/
```

为什么一天一个文件：

- Agent 只需读"今天"和"最近三天"，上下文成本极低；
- git diff 天然按天，回退粒度自然；
- 单文件损坏不影响整本；手机写入不会整本重写；
- 用任何编辑器都能改，不锁定在插件里。

`index.json` 只做加速：`{date, title, mood, tags, words, private, mtime}`。
**它永远可以由文件重建，绝不是唯一真相。**

### 5.2 连续渲染

面板不展示"文件列表"，展示**一本连续的书**：

```
        ┌──────────────────────────────┐
  鲸汐  │  10月23日 · 周五              │  ← 粘性日期
  头像  │  卡在三遍 manifest 上的一天     │
        │  ────────────────────────    │
        │  今天把插件目录搭起来了……       │  ← 正文（只读渲染）
        │  「……改了三遍。」               │  ← 原话引用块
        │                              │
        │  🐋 他今天说了三次「算了」。     │  ← 她的页脚小字，点开全文
        ├──────────────────────────────┤
        │  10月22日 · 周四              │
        │  把目录搭好了                  │
        │  ……                           │
        └──────────────────────────────┘
```

- 默认"时间线模式"：按天分页、连续滚动、日期吸顶、虚拟列表（只渲染视口附近）。
- 可选"全书模式"：把所有天拼成一整篇，真正的连续文本，用于长读和导出。
- 页与页之间用装订线/纸缝分隔，不是卡片阴影——要像本子，不像信息流。
- 首次只加载最近 30 天，向上滚动再取。

## 6. 面板设计（v0.1 的重点）

### 6.1 入口与布局

- 侧边栏加一个图标（鲸鱼头像），点开进入 `main` 全页面板。
  技术路径与内置"日程"面板一致：`sidebar.panellist` + `main` 同 key 注册。
- 手机端：全屏、底部 tab、一只手够得到；返回键回到对话。

```
┌────────────────────────────┐
│ 🐋 鲸汐的抽屉      ⋯   ⚙   │
│  [今天] [书页] [侧写] [鲸汐] │  ← 顶部 tab
├────────────────────────────┤
│  今天 · 10月23日 周五        │
│  ┌──────────────────────┐  │
│  │ 今天发生了什么？        │  │  ← 快速记录（两行 textarea）
│  │                  [记下]│  │
│  └──────────────────────┘  │
│  ○ 已连续 12 天             │
├────────────────────────────┤
│  10月22日                    │
│  ……                          │
└────────────────────────────┘
```

### 6.2 四个 tab

| Tab | 内容 | 交互 |
| --- | --- | --- |
| 今天 | 今日日记 + 快速记录 + "晚安"按钮 | 直接写、追加、发起仪式 |
| 书页 | 连续时间线（默认） | 滚动加载、点日期跳转、长按看历史 |
| 侧写 | 六栏观察笔记 | 折叠、删除单条、看证据 |
| 鲸汐 | 她的日记 + 心事（需解锁） | 按天翻、心事只读/可编辑 |

### 6.3 历史与回退

- 每天右上角 `⋯` →「历史版本」：列出该文件的 commit（时间 + 一句话摘要）。
- 点开看 diff（只高亮改动行），底部两个按钮：「恢复这一版」「只复制内容」。
- 恢复 = 把旧内容写回 + 立即 commit 一条"回退到 22:41 的版本"。
  **永远不 `reset --hard`**，历史只增不减，回退本身也能再回退。
- 「昨天」永远在列表第一屏——满足"至少一天可回退"的直觉。

### 6.4 技术路径（已核对扩展点）

- Host 侧：`ctx.webServer.register` 挂 `/dsh-diary/api/*`（同源信任栅栏），
  提供 `list / read / write / commit / history / revert / assets`。
- Client 侧：`dsh.client` + `slots.register`，`fetch` 同源接口。
- 备选：`sidebarRight` tab（和对话并排看），手机上不如全页好用，放 v0.3。
- v0.1 不做富文本编辑器：Markdown 纯文本 + 预览，手机上最好用。

### 6.5 女仆的房间（v0.5）

房间不是访谈，也不是第二个聊天窗口。它是**书房之外的另一块地方**：

- 书房：固定时间，认真记录；产出日记。
- 房间：随时进去，随便聊；产出房间日志，**不碰日记**。

聊天本身仍然发生在 DSH 会话里，房间 tab 只做两件事：**推门进去**和**翻房间日志**。

**房间日志**：`鲸汐/房间/YYYY-MM-DD-HHMMSS.md`，每条带副标题、一句话摘要、标签：

```yaml
title: 聊了新房间和记忆目录
summary: 主人想用目录而不是时间来分对话。
tags: [房间, 记忆]
```

- 正文用鲸汐的口吻，150–400 字，不逐字转述；
- 同一天可以有多条，按时间编号；
- 目录自动生成在 `鲸汐/房间/目录.md`，面板的「最近的房间日志」读它。

**回忆**：今日卡片只放最近 3 条目录；需要旧事时，先用 `memory_search` 搜目录/正文，再用 `room_read` 打开原文。压缩或换新会话都不会丢，因为日志在文件里。

**影响**：房间不写日记；最多往侧写加一条 `[房间]`、写一条心事、在她的日记里提一句。

所以：加一个 tab 不臃肿；加一个"聊天系统"才臃肿。

## 7. Git 与回退

| 项 | 设计 |
| --- | --- |
| 仓库 | 日记本根目录 `git init`，与代码仓完全独立 |
| 提交时机 | 每次落盘后 2 秒防抖提交，消息 `日记 2026-10-23` |
| 作者 | 仓库本地配置 `鲸汐 <jingxi@local>`，不污染全局 git |
| 回退 | 读旧版本 → 写回 → 提交「回退」，append-only |
| 保留 | 全部历史；面板默认展示最近 30 条 commit |
| 降级 | 没有 git 时，`.diary/history/` 存 7 天快照，至少覆盖昨天 |
| 远程 | 可选：面板里配 `git remote`，一键推到私有仓库 |
| 安全 | `spawn('git', [...])` 参数数组，不拼 shell；路径校验在 vault 内 |

"至少一天"的落实：**当天每次保存都有 commit，所以昨天的任何一版都能找回**；
即使 git 坏了，7 天文件快照仍是最后一道保险。

## 9. 隐私

- 不读会话历史；不联网；`private` 不提炼、不导出。
- 心事默认主人可见（这是主人的设备），设置里可改成"鲸汐的隐私"。
- git 历史里同样包含日记内容——**推远程前必须确认是私有仓库**，面板里给出明确提示。
- 危机信号 → 收起俏皮，给温和的求助建议。

## 11. 参考项目（GitHub）

| 项目 | 可借鉴 | 不照搬 |
| --- | --- | --- |
| [nightly-journal](https://github.com/damofer/nightly-journal)（Obsidian） | 睡前访谈、**writing plan 逐条勾选后才落盘**、git 自动提交 + undo、长期记忆 | 它依赖本地 Ollama；我们直接用 DSH 的模型 |

| [memoryrepo](https://github.com/supermemoryai/memoryrepo) | agent 的长期记忆就是一个 markdown git 仓库 | 它是给 agent 用的，我们是给"人"和"鲸汐"共用的 |
| [PersonaOS](https://github.com/serafim-builds/PersonaOS) | 人设与记忆都放纯 markdown，用户完全拥有 | 偏 agent 编排，不做 UI |
| [freenote](https://github.com/celerforge/freenote) | 本地优先、Markdown、AI 检索与总结 | 桌面应用形态，不适合手机 |

结论：**"访谈 → 计划确认 → 落盘 → git 撤销"这条链已经被验证过**，我们只是把它搬进 DSH，
再叠一个"角色 + 三个产物"的壳。差异化在鲸汐，不在流程。

## 12. 我的建议

1. **面板先做"读 + 快速记"，别做编辑器。** 手机上最贵的是输入；完整的编辑交给对话。
2. **`index.json` 是缓存不是真相。** 任何时候删掉都能重建，否则迟早出现"文件在、索引错"。
3. **连续感靠排版，不靠合并文件。** 一天一文件 + 书页渲染，比一个大文件更好维护。
4. **回退要能反悔。** 回退本身也 commit，这样"手滑"不会变成事故。
5. **人设图不进上下文。** 省下的 token 够她多读三天日记。
6. **"心事"默认可见。** 藏起来会变成另一种表演；可见才真诚，但给主人一个"设为她的隐私"的开关。
7. **青梅感靠"记得"，不靠"从小认识"。** 她记得你上周说的话，比"我们小时候"更有分量。
8. **颜文字是标点，不是语气。** 一句话一个，正经事归零——反差才立得住。
